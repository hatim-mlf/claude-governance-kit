claude-governance-kit

Governance for AI-assisted development.

An execution ledger, a defect tracker, a reporting protocol, behavioural skills, enforcement hooks, and a generated dashboard — installed into any git repository, so what an AI session started, changed, verified, and left open is always written down, and always visible.

01Why it exists

AI coding sessions produce work with no memory. A fix gets recorded as done before anyone confirmed it. A failure is logged nowhere. A decision is re-litigated every session. A credential is committed once and lives in history forever. This kit is the discipline layer that prevents that — as files, scripts and hooks inside the repository itself, not as an external service.

Work is commissioned by a session prompt, recorded in the ledger as it happens, written up by the reporting skills, gated by the pre-commit hook, and published to the dashboard automatically at session end and per turn — idempotently, keyed on what actually changed.

03What installs where

Path in target projectWhat it is
governance.config.jsonThe one config file: project name, and every root the dashboard reads, each with a sentinel file that proves the root is real.
ledger/Append-only execution log, one file per ISO week. Every task: reserved before starting (with a machine-read timestamp and an id from next-ledger-id.sh), closed with a summary, touched files, and how it was verified.
reports/One folder per report type — bugs, errors, audits, sessions, verification — each written with its own skill, each citing its ledger id.
reports/bugs reports/BUG_TRACKER.mdThe live defect register. Status vocabulary separates fixed, unverified from fixed, verified.
STRUCTURAL_PROBLEMS.mdThe second register: tooling, layout and process defects, plus a Lessons table.
.claude/skills/14 skills. Six record what happened (bug/error/audit/session reports, session prompt, dashboard sync); eight decide what to do (diagnosing-bugs, grill-me, codebase-design, writing-for-agents, tdd, project-code-review, to-tickets).
.claude/rules/Path-scoped invariants that load only when matching code is opened, plus a README on how to write one.
scripts/The pre-commit gate, the hook installer, the ledger-entry timestamp checker, the id allocator, the dashboard sync runner.
bug-tracker-dashboard/A local Vite/React app. Generators turn the Markdown into typed data; four views render it. No backend, no accounts.

04The design rules

The ledger is the spine

Reserve before starting, close when done, cite the entry id from every other record. Nothing is duplicated into the ledger; it points outward.

Fixed ≠ verified

A commit is a claim. Only named evidence — a capture, a test run, a scenario — moves a row to verified. The dashboard renders the split.

Loud failure, never silent skip

Generators validate roots by sentinel and die loudly. The sync hook logs every skip to a file outside the repo — a log inside a repo you cannot find is not a log.

Block only what is never legitimate

The pre-commit hook blocks credentials and warns on everything else. A gate that blocks real work gets bypassed until it means nothing.

No cron

The dashboard syncs inside sessions only. A scheduler would be a second writer to the working tree — the problem the system exists to prevent.

The system is a means

A defect in the system gets its own register row — but filing it does not mean stopping application work to fix it.

05Install

git clone https://github.com/<you>/claude-governance-kit
cd claude-governance-kit
./install.sh /path/to/your/project

# then, in the target project:
cd bug-tracker-dashboard/app
npm install && npm run sync && npm run dev   # → http://localhost:5173

The installer asks for a project name, short id, and source directory; copies everything in without overwriting anything that already exists; writes governance.config.json; and installs the git pre-commit hook.
